# 固定第一项与派遣优先级

生产选择方法固定第一项，干员按满足安全条件的未精二天猫、伊桑、古米排序。
原天猫安全出口评估保留；没有可派干员或第一项不可用时直接选最后一项，不改选第二项。
只有确认天猫实际派出后启用额外避战，伊桑/古米离队沿用原地图规则，进入下一层解除天猫离队限制。

`lifecycle-payloads.json` 来自实际生产方法的受控设备/识别回放，包含六个成功派遣和两个主动离开。
重试、保存失败、第一项不可用及实际选择的最后索引另有断言；天猫安全性与精英化、干员组合全量枚举。
`producer-events.json` 再通过实际 Session、TaskPort、日志器导出；取消不声明已派出。
`evidence-frame.jpg` 是受控契约图，不是新版实机派遣画面。

20261024 的随机选择历史样本继续保留，并在同一次原生/消费者回归中验证。
新 metadata `fixed_first_option` / `unpromoted_core_then_ethan_then_gummy` 不回填旧未知选择，
新旧原始/图片/签名 schema、识别任务族与派出/归队配对规则均不变。
