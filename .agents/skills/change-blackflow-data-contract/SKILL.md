# 采集数据契约变更

先读本仓库 [原始契约与联动说明](../../../docs/blackflow/data-contract.md)。定位本次 `lubiao-analysis` 工作区后，读取其中 `docs/data-pipeline/coordination.md`；目录名可由 Git remote/工作区映射确定，不依赖固定盘符。

检查本次 BlackFlow 修改是否改变字段或事件时机、图片路径/布局、地图与事务含义、采集范围、封包或签名。若无影响，记录依据；若有影响，列出生产者、独立验证器、标准化和专题统计的对应修改，使用同一批契约样本验证。

涉及运行时识别或新增截图任务时，联读 analysis 的 `docs/data-pipeline/task-families.md`。区分只截图、部分识别、完整识别，尽量保留已识别字段供下游整理；购买白名单结果不声明完整货架。日志缺失或部分识别时，下游复用已有原图和分类识别器补齐；商店保留拼接货架、截图覆盖范围及刷新轮次。归队弹窗保留明确楼层入口归属，失与得保留 selected_name、交换轮次及奖励阶段，便于配对而不重复 OCR。

原始契约与封包验证的权威在本仓库；analysis 固定契约版本并维护处理/分析及业务插件。PtilopsisBot、quark-timed-sync 保持通用，领域规则经插件接入，宿主协议未变时无需强制改宿主。

完成前说明旧数据兼容、未知版本处理、缓存/人工审核失效、受影响的分子分母和测试。三层精简采集不补四五层阴性，本地签名不当作官方来源证明。涉及发布时先使消费者兼容新旧契约，再发布新采集器；本流程不扩大当前任务的发布授权。
