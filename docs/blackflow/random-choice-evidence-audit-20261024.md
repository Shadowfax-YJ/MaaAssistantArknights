# BlackFlow 随机选择证据检查（2026-10-24）

范围是当前工作区 BlackFlow 客户端的随机选择调用，以及小八界这条代表性的游戏随机落点链。
不是对所有游戏随机事件或奖励机制的完整审计。本次实施先行一步、货从口出和失与得的采集与消费修复，
没有发布、部署、替换实例、改变随机权重或修订历史包。

## 先行一步：本次修复

旧版 `confirm_expedition_dispatch` 的最小生产方法回放输出
`route_state_updates=1, archived_dispatch_facts=0`：普通日志和路线状态回调没有保存归档事实。
初选的返回值也被丢弃，`next_event` 一次可连续快进多次，之前没有逐次离页证据。

新增专用、返回保存结果的观察器。候选、计划、逐次点击、选择页确认、派出前姓名/状态、
派出尝试、最终确认、取消/未决分开写入归档；截图与确认由稳定编号和原节点事务关联。
仅在有派出点击且随后看到对应事件页或真实地图时确认；选择页和网络覆盖优先排除。
每次过渡快进前各存一帧，不能用一次截图覆盖内部多次点击。状态更新在确认落盘之后执行。
失败或未决会停用父任务并把 Session 标为失败，不宣称完整采集；原干员资格、分组随机权重、
精二规则预测与核心离队避战规则保持。完整语义及下游边界见 `data-contract.md`。

## 货从口出：已补实际选择与确认

这是当前 BlackFlow 配置中启用 `choice_groups.random` 的事件。先随机打乱可选组，再按
`select_analyzed_option` 的实际成功结果进入后续流程；通用 `RoguelikeEvent.choose_option`
在随机组执行前生成，不能代表最终实选。现有候选拼接图和普通点击日志不能单独恢复实际项。
现在保存完整拼接候选图、候选原文、随机组顺序、逐次点击坐标和实际编号，使用固定 choice_id 与
原节点 source_context 关联。重试沿用同次顺序；后续奖励页不复用初选下标。仅在实际点击后看到
真实地图，或连续两帧出现不同的新选项/获得类弹窗时确认；不把原候选列表的局部可见子集当作换页。
002 的真实加工品奖励弹窗另存 cargo-reward.jpg 回归，不要求在原领奖分发之前先回地图。
网络覆盖优先等待，未决停止；先前点击未决时不再切换另一项并错误归因。随机权重和候选范围保持。
确认截图与日志先落盘，失败停止父任务及 Session。消费者仅确认完整证据链，计划、未决、冲突分列。

## 失与得：已补失败传播与初选确认

`RoguelikeStageEncounterTaskPluginSacrifice::handle_sacrifice_event` 在点击前用
`event-choice` 保存随机初选编号/原文；另有 `item-selected` 与 `exchange-reward`。
这些比先行一步旧版多，但 `report_sacrifice` 返回 void，事件详情观察器保存失败只警告；
初选记录也缺少独立的点击/换页确认，不能把 `event-choice` 升格为已接受选择。
现在观察器返回保存结果；任一要求的截图/日志失败立即停止，不再选择、换出、领取或继续库存扫描。
初选使用同一选择证据链，按节点与交换轮次编号；进入实际物品选择页或文明处理后的独立页面才确认。
event-choice 仍表示计划，exchange-reward 仍仅表示奖励出现；新增领取尝试和已发出点击，不冒充已领取。
初次随机、第二轮第一项、物品随机和文明库存差分策略保持。消费者不把新增生命周期算成额外交换。

## 秘境行商误购：同次修复

003 的 run-20261024-004626-766781 三层货架同时有种子与种荚；旧购买白名单识别将种荚改成种子、
血蕈改成血橙（两者相似度均 0.5）。重定位因两个同名种子而拒绝真正种子，刷新后又买下被误标的种荚。
现在先用购买候选与全部零件名称的并集识别身份，再按原名单筛选；不足四字不做编辑距离纠正。
真实货架原图和来源存于 blackflow-merchant/20261024，原生回归确认只有右上真实种子一个候选。
不改变购买优先级、配额、价格预算或旧归档中的声明；历史 actual_item_name 不能因此升级为独立视觉证明。

最终验证：MaaCore 编译、105 项生产方法回放、285 项原生检查、369 项路由/归档、68 项下游检查及七项
共享契约检查通过。没有进行完整实机对局，也未发布或替换运行实例。
